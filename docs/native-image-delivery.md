# 이미지 제작·캡처·묶음 전달

사용자 요구는 실제 도구로 만든 썸네일·본문 이미지, 직접 캡처한 원문, 모바일에서 여러 장을 한 번에 저장할 수 있는 네이티브 이미지 묶음이다.

기준 절차:
https://github.com/yunsj0121/naver-blog-seo-writer/blob/6df8430aa65715a5866ea718660e46031ff80799/docs/pipeline-redev.md#L113

## 제작과 전달을 구분한다

`economicissue build/draft`는 원고와 이미지 입력용 레이아웃·실제 캡처를 준비한다. Python CLI가 ChatGPT의 이미지 생성 또는 첨부 도구를 직접 실행했다고 표시하지 않는다.

`delivery.json`에는 각 파일의 실제 종류, 해시, 필요한 생성 결과 수, 실제 캡처 첨부 수, 묶음 순서가 기록된다. 생성 입력은 `generation_input`, 원문은 `source_capture`로 구분한다. 문서 생성만으로 완료 상태로 바꾸지 않는다.

## 실제 제작 이미지

1. 작업 에이전트가 `image-generation.json`과 확정 원고를 읽고 입력 PNG를 확인한다. `input_path`는 최종 묶음 폴더 기준 상대 경로이므로 도구에 넘길 때 절대 경로로 해석한다. 저장된 해시도 확인한다.
2. 각 작업은 실제 `image_gen.imagegen`으로 실행한다. `referenced_image_paths`에는 해당 입력 PNG 한 장을 넣는다. 썸네일은 1:1, 큰 글씨이며 승인된 문구·숫자·단위를 유지한다.
3. 실제 반환 객체를 현재 세션의 저장소에 보존한다. 파일 경로나 `view_image` 데이터 URL을 반환 객체라고 꾸미지 않는다. 생성 결과의 한글·수치·비율을 직접 확인한다.
4. 같은 응답에서 결과들을 입력 순서대로 `generatedImage(result)`에 전달한다. 같은 글의 결과 사이에 다른 미리보기나 파일 링크를 끼우지 않는다.
5. 실패하면 성공 결과를 보존하고 실패한 작업만 다시 실행한다. 전체 이미지를 다시 생성하지 않는다. 반환 형식에 없는 `content` 등의 필드를 가정하지 않는다.

`generatedImage`는 작업 에이전트 실행 환경의 출력 함수이며 Python 함수가 아니다. 아래 결과들은 반드시 실제 이미지 생성 도구의 반환 객체여야 한다.

```javascript
for (const result of orderedActualImageGenResults) {
  generatedImage(result)
}
```

## 실제 원문 캡처

브라우저에서 실제 원문·영역을 확인해 캡처한다. `raw-captures/`에는 밑줄 전 원본을 보존한다. 출처·영역·파일 해시를 기록하며, 캡처 실패를 가짜 화면으로 메우지 않는다. 실패한 원문은 코드블록 밖에 바로가기를 제공한다.

캡처는 이미지 생성 작업에 넣지 않는다. 해시로 확인한 실제 PNG를 지원되는 이미지 첨부 기능으로 별도 묶음에 직접 첨부한다. `generatedImage`에 캡처 파일이나 미리보기 URL을 넣지 않는다. 미리보기 이미지가 모델에게 보이는 것과 사용자에게 실제 첨부되는 것은 다르다.

## 완료 판정

이미지 생성·캡처 성공, 이미지 검수, 사용자 첨부, 모바일 묶음 저장은 서로 다른 단계다. 실제 네이티브 이미지 묶음과 일괄 저장이 확인되지 않으면 pending 상태를 유지한다. 사용자가 여러 장을 개별 저장해야 한다고 알려주면 미완료다.

마크다운 이미지 나열, HTML, ZIP, 합본, 개별 PNG 링크로 자동 대체하지 않는다. 해당 첨부 기능이 확인되지 않으면 그 부분을 미확인으로 보고한다. 사용자가 따로 요청한 보조 내보내기만 `write_image_gallery`로 만들 수 있다.
