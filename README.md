# economicissue

3040 독자가 자기 돈과 비교할 수 있는 네이버 생활경제 글을 제작합니다.
기본 결과는 **공백 포함 약 1,500자 원고 + 1:1 썸네일 + 본문 이미지 4장 + 해시태그 20개**입니다.
벤치마킹한 블로그의 문장·이미지를 복제하지 않고 소재 선택, 숫자 비교, 자료와 해석을 연결하는 구성만 참고합니다.
네이버 게시 작업은 사용자가 합니다.

## 설치

Python 3.11 이상에서 저장소 루트 기준으로 실행합니다.

```sh
pip install .
python -m playwright install --with-deps chromium
```

한글 폰트는 맑은 고딕, 나눔고딕, Noto Sans CJK 순으로 찾습니다.
다른 폰트는 `KOREAN_FONT`, 별도 Chromium은 `CHROMIUM_EXECUTABLE_PATH`로 지정합니다.
브라우저는 환경의 HTTP(S) 프록시를 사용하며 인증서 검증을 끄지 않습니다.
프록시 CA가 필요한 환경은 운영 환경의 브라우저 신뢰 저장소에 CA를 설치해야 합니다.

API 원고·제목 작성에는 다음 환경 변수가 필요합니다. `.env.example`은 설명용이며 자동으로 읽지 않습니다.

```sh
export OPENAI_API_KEY=...
export OPENAI_MODEL=gpt-4.1-mini
```

Windows PowerShell은 `$env:변수명="값"` 형태를 사용합니다. 키는 커밋하거나 원고에 넣지 않습니다.
설치·테스트는 유료 API를 호출하지 않습니다. `topics`와 `draft`는 각각 별도 유료 호출이며 결과를 캐시합니다.

## 제목 후보를 고른 뒤 제작

```sh
# 최근 원문을 수집하고 제목 후보 10개만 제시합니다
 economicissue topics
# 사용자가 3번을 골랐다면 기존 근거로 원고와 이미지를 만듭니다
 economicissue draft --candidate 3
```

`run`만 실행해도 `topics`처럼 후보에서 멈춥니다. `run --candidate 3`은 기존 후보의 3번을 제작합니다.
제목·주제를 자동 선택해 바로 제작하던 이전 `run` 동작은 더 이상 사용하지 않습니다.

- `output/title_candidates.json`: 번호, 제목, 관점, 연결된 근거, 근거 묶음 해시
- `output/research.json`: 후보별 확인한 원문 발췌, 게시일, 원문 확인 상태, 캡처 후보
- `output/selected_draft.json`: 선택 후 생성된 원고. 검사 실패 시 이 파일을 고쳐 `build` 가능
- `output/brief.json`: 선택한 후보의 근거와 제목·주제 고정 정보

같은 원문의 다른 관점이 후보에 포함될 수 있습니다. 같은 원문의 후보는 같은 사건 키를 사용하므로 중복 제작을 막습니다.
후보와 근거 파일이 다르거나 선택할 때 최근 일주일을 벗어났으면 중단합니다.
날짜가 확인되지 않은 자료는 최신 소재의 출발점으로 쓰지 않습니다.
제목·주제는 작성 후 다시 확인하며 모델이 바꾸면 완성본으로 내보내지 않습니다.

### API 없이 준비·수동 작성

```sh
# 실제 공개 원문으로 교체하세요. --url은 여러 번 지정할 수 있습니다
 economicissue prepare --url https://example.com/actual-report
 economicissue build --draft draft.json
```

`prepare`는 유료 호출 없이 근거, `output/instructions.txt`, `output/schema.json`을 만듭니다.
이 파일을 작성 도구에 전달해 받은 JSON을 `draft.json`에 저장합니다.
약 1,500자·해시태그·이미지 구조 검사는 수동 원고에도 동일합니다.
선택 후 자동 작성에 실패했다면:

```sh
 economicissue build --draft output/selected_draft.json
```

길이 검사 실패를 숨기기 위해 문장을 자르거나 같은 설명을 추가하지 않습니다.
검사 오류에 실제 글자 수를 표시하며 자동 유료 재호출은 하지 않습니다.

## 기본 편집 규칙과 검사

`policy.json`에서 변경할 수 있습니다.

| 설정 | 기본값·의미 |
|---|---|
| `image_count` | 5, 썸네일 포함 총 3~6장 지원 |
| `length` | 목표 1,500자, 허용 1,400~1,600자 |
| `hashtag_count` | 서로 다른 해시태그 20개 |
| `blank_line_between_sentences` | 한 문장 한 줄, 문장마다 빈 줄 하나 |
| `spread_images` | 이미지를 서로 다른 관련 문단 뒤에 순서대로 배치 |
| `minimum_data_images` | 캡처·표·그래프를 합쳐 본문에 최소 2장 |
| `mixed_visuals` | 본문 이미지 종류 두 가지 이상 |
| `thumbnail_from_card` | 첫 자료 이미지 전체를 보존해 1:1 썸네일에 조합 |
| `capture` | 원문 일부 캡처 사용 |

글자 수는 **본문과 해시태그, 그 사이 공백·줄바꿈**을 셉니다.
제목·자료 출처·이미지 삽입 안내는 제외합니다.
문장 끝 마침표는 생략하되 URL과 소수점은 보존합니다.
이미지 문구 줄바꿈은 원고 문장 간격 규칙과 분리합니다.
`~해요/~예요/~죠`와 `~습니다/~입니다`를 섞어 쓰도록 지시합니다.
말투·주제 관련성·출처와 해석의 의미 일치는 기계적 개수 검사만으로 보증하지 않습니다.

흐름은 생활 상황 → 확인한 사연·자료 → 숫자를 생활 단위로 비교 → 해석과 선택 기준입니다.
사연형·상황형·비교형 도입을 자료에 맞게 고르며 실제 체험을 지어내지 않습니다.
나이와 자산만으로 사람의 인격이나 미래를 단정하지 않습니다.
평균/중앙값, 개인/가구, 발표일/기준연도, 월/연 금액을 구분합니다.

## 자료 수집과 최신성

기본 탐색은 블라인드 공개 게시판, 하나금융연구소, KB경영연구소, KOSIS RSS, 국가데이터처 RSS,
주택금융공사 공식 안내를 제한된 범위에서 직접 확인합니다.
선택적으로 `queries`, `official_queries`와 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 설정하면 네이버 검색도 사용합니다.
뉴스·커뮤니티는 최근 7일, 참고용 보고서·통계는 120일이 기본 범위입니다.
보고서가 오래되었어도 배경 자료로 쓸 수 있지만, 제목 후보에는 최근 7일의 확인된 원문을 하나 이상 연결해야 합니다.

원문 URL·내용 해시로 중복을 제거하고 생활 상황·선택 갈등·결과 비교를 평가합니다.
편집 점수는 클릭률 예측이나 사실 검증 결과가 아닙니다.
목록 성공과 본문 성공을 구분하며 `output/collection_status.json`에 출처별 상태를 기록합니다.
접근 제한·로그인·삭제·CAPTCHA는 우회하지 않습니다. 사이트가 수집을 허용하지 않으면 제외합니다.

일반 HTML은 텍스트 추출에 더해 Chromium으로 실제 본문을 확인하고 짧은 문단·표·이미지의 실제 CSS 경로를 기록합니다.
`browser_sites`에 호스트별 본문 selector 목록을 지정할 수 있습니다.
브라우저 확인이 실패한 일반 보고서는 충분한 정적 본문만 사용하고 실패 사유를 남깁니다.
**블라인드 개별 게시물은 브라우저에서 본문이 확인되지 않으면 사용하지 않습니다.**
사이트 구조가 바뀌면 selector 수정이 필요할 수 있으며 접속 성공을 항상 보장하지 않습니다.

PDF는 실제 링크로 다운로드해 최대 40페이지까지 읽고 페이지 번호를 남깁니다.
공식 HTML 요약만으로 PDF 수치를 추정하지 않습니다. 스캔 PDF OCR은 지원하지 않습니다.
KOSIS의 RSS 갱신 알림과 실제 통계 값은 구분합니다.
수치 API는 `KOSIS_API_KEY`와 운영자가 발급받은 `kosis_series` 명세가 필요합니다.
키 없이 API 조건이나 수치를 추정하지 않습니다.

## 원문 캡처와 이미지

본문 이미지 `cards`에는 다음 항목이 있습니다.

- `visual`: `evidence`(원문 일부), `table`(비교표), `chart`(막대그래프), `explanation`(설명)
- `source_ids`, `after`: 근거와 삽입 문단 번호
- `capture_id`: 브라우저가 확인한 후보 ID. CSS selector를 모델이 만들지 않습니다
- `columns`, `rows`: 표·그래프 데이터. 다른 종류에서는 빈 배열

표는 2~3열·2~6행, 셀 24자 이하입니다. 그래프는 항목과 동일 단위의 음이 아닌 숫자 2열입니다.
표·그래프의 숫자는 연결 원문 안에 존재하는지 검사합니다. 숫자의 단위·대상·문맥 일치는 게시 전에 검토합니다.
검증되지 않은 수치를 생성 이미지로 포장하지 않습니다.
Pillow가 만드는 PNG는 생성 입력용 레이아웃입니다. 게시용 제작 이미지는 작업 에이전트가 실제 이미지 생성 도구로 만들며 별도 사용량이 발생합니다. CLI나 GitHub Actions가 채팅의 이미지 생성 도구를 자동 호출하지는 않습니다.

자동 캡처는 브라우저가 실제 확인한 짧은 본문 일부를 사용합니다.
`capture_rights`는 공개 원문 중 비평·설명에 필요한 일부 인용이라는 이용 근거를 기록합니다. 모든 사진의 이용 허락을 뜻하지 않습니다.
사진·그림은 자동으로 가져오지 않고 구체적인 이용 근거를 확인한 `--captures` 명세로 지정합니다.
실제 원문을 캡처하고 원본 PNG를 `raw-captures/`에 보존합니다. 전달용 캡처에는 필요한 밑줄만 표시하고, 원문을 다시 그리거나 이미지 생성 도구에 넣지 않습니다. 출처는 원고 밖의 링크로 제공합니다.
본문이 바뀌어 저장한 내용 해시가 다르거나 캡처가 너무 길면 중단합니다.
캡처 실패 이미지는 원문 캡처 불가 안내와 해설로 대체하고, 원문 링크와 실패 사유를 별도 파일에 남깁니다.

명시적 캡처의 예시 형식 (실제 source_id, selector, 원문 구절로 바꿔야 합니다):

```json
[
  {
    "card": 2,
    "source_id": "s1",
    "selector": "#actual-article p:nth-of-type(2)",
    "rights": "확인한 이용 근거",
    "highlights": ["캡처 영역에 실제로 있는 핵심 구절"],
    "mask_selectors": ["#actual-profile"]
  }
]
```

```sh
 economicissue build --draft draft.json --captures captures.json
```

1번은 썸네일, 2번부터 본문 이미지입니다. 사진 단독 영역은 `kind: "image"`를 지정합니다.
개인정보는 정확한 `mask_selectors`로 가립니다. 명세에 없는 개인정보가 없는지는 검토해야 합니다.
썸네일은 1080×1080이며 자료 전체를 담아 숫자를 자르거나 전체를 어둡게 하지 않습니다.
썸네일 글자는 80~112px로 크게 배치하며 문구가 길면 줄여서 작성합니다. 본문 이미지에는 핵심 메시지·숫자·출처·계산 조건을 남기고, 표 재구성 여부나 실제 적용 금리가 아니라는 반복 안내는 표시하지 않습니다.
본문 캡처는 가독성을 위해 원래 비율을 보존합니다. 긴 원문 전체 대신 핵심 일부로 범위를 좁힙니다.

## 결과 파일

`output/<주제해시>/`에 완성된 묶음만 저장합니다. 원문 캡처가 실패해도 실패 사실과 원문 바로가기를 표시한 완성 묶음을 만듭니다.

- `post.txt`: 이미지 삽입 위치·출처가 포함된 원고, 맨 마지막 해시태그
- `copyable_post.md`: 게시 본문을 코드블록으로 감싼 복사용 원고, 아래에 출처 바로가기 링크
- `01_thumbnail.png`, `02_body.png` 등: 이미지 생성 입력용 레이아웃 또는 실제 캡처 (`image_review.json`으로 구분)
- `raw-captures/`: 밑줄 처리 전 실제 원문 캡처
- `preview.html`: 코드블록 원고 복사 버튼, 본문·이미지 미리보기, 출처 바로가기
- `capture_failures.json`: 원문 캡처에 실패한 자료와 실패 사유; 해당 출처 링크는 복사용 원고와 미리보기에 별도로 표시
- `image-generation.json`: 실제 image_gen으로 제작할 입력 파일·확정 문구·순서
- `review.json`: 글자 수·해시태그 수·선택 제목·모델 사용량
- `image_review.json`: 실제 이미지 종류·캡처 출처·영역 기록
- `sources.json`, `draft.json`, `manifest.json`, `delivery.json`

`delivery.json`은 `pending_generation_and_native_attachment` 상태의 작업 지시서이며 첨부 영수증이 아닙니다. 실제 생성 결과를 같은 응답에서 연속 반환하는 [네이티브 이미지 전달 절차](docs/native-image-delivery.md)를 적용해야 합니다. 원문 캡처는 실제 PNG를 별도로 묶어 첨부합니다.
마크다운 이미지 나열이나 `view_image` 검수로 전달을 끝내지 않습니다. HTML/ZIP 내보내기 함수는 보조 기능으로만 유지하며 기본 제작에서는 만들지 않습니다. 실제 묶음 첨부와 일괄 저장은 수신 앱에서 확인해야 합니다.

## GitHub Actions

`Build issue package`에서:

1. `prepare`: 자료만 수집, 모델 호출 없음
2. `topics` 또는 `run`: 제목 후보 10개를 만든 뒤 정지, Artifact의 후보 파일 확인
3. `draft`: 선택 번호와 2번 실행의 `research_run_id`를 입력해 해당 Artifact를 가져와 제작

`OPENAI_API_KEY` Secret이 제목·원고 작성에 필요하며 모델은 `OPENAI_MODEL` Variable로 지정합니다.
선택적으로 KOSIS와 네이버 키를 설정합니다. 임의의 예약 실행이나 네이버 자동 게시를 추가하지 않습니다.
캡처 명세는 저장소 내 JSON 파일 경로를 입력할 수 있습니다.
결과 Artifact에 원문 발췌·캡처가 포함될 수 있으므로 공개 가능한 자료만 사용합니다.
캐시가 아닌 명시한 실행의 Artifact로 후보와 근거를 연결합니다. Artifact가 만료되면 새로 수집해야 합니다.
